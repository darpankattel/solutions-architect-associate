# AWS Simple Storage Service (S3)

AWS S3 is a Storage service, not a database, but block/file storage service, advertised as infinitely scaling. We store files in **buckets** (quite similar to directories), and the files are called **object** instead.

## Usecases
- Static Website
- Data Lake & big data analytics
- Storage, and backup
- Archival
- Media hosting
- Hybrid Cloud storage

## Buckets
Buckets, the *bucket* to store objects, need to have globally unique name, across all regions, and across all accounts. But still, buckets are defined at the region level. We have some strong naming conventions for buckets
- no capitali letters
- 3-63 characters long
- not an ip
- can start with numbers
- must not start with the prefix xn--
- must not end with the suffix -s3alias

Amazon S3 supports two types of buckets. You can't change the bucket type after you have created the bucket.

- General purpose buckets: Recommended for most use cases and access patterns. General purpose buckets are the original S3 bucket type. They allow a mix of storage classes that redundantly store objects across multiple Availability Zones.
- Directory buckets: Recommended for low-latency use cases. These buckets use only the S3 Express One Zone storage class, which provides faster processing of data within a single Availability Zone.

## Objects
Objects, or files, have a key, which is the full path to the object, like:
s3://my-bucket/my-file.txt, is the key of the object.

Well, there is no concept of directories in the buckets, but the UI is designed to preview as such for ease.

So, keys are very long, with slashes.

An object can be at max of 5TB in size. But, to upload a file more than 5GB, we should use multi-part upload.

S3 objects have some metadata, like version ID if versioning is enabled.

## Security in S3
### User based
Using **IAM Policies**, we can say which IAM user can access which apis.

### Resource based
- Using **bucket policies**
- **Object ACL**
- **Bucket ACL**


An IAM principal can access an object if:
(User IAM policy allows it) | (resource policy allows) & no explicit deny

Objects are encrypted in S3, in rest and in transit, we will learn about it later.

## Bucket Policies
They are the JSON based policies that have some statements, that provides an **effect** (either allow or deny) for a **principal** of doing an **action** to an **resource**, in some **condition**.

Example:
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowPublicRead", // just the name of a statement, can be anything
            "Effect": "Allow", // Allow | Deny; whether to allow or deny the principal this action on the resource
            "Principal": "*", // the IAM principal can be an IAM User, or roles, etc.. 
            "Action": [ // a action, or *, or list of actions that can be allowed/denied based on effect
                "s3:GetObject", // can get s3 objects within the below listed resource (bucket)
            ],
            "Resource": "*" // expliclitly mention which s3 resource with its ARN or *
        }
    ]
}
```


We can use these above policies to grant public acess to bucket, or force objects to be encrypted at upload, or even grant access to another account.


## S3 Storage Class

- S3 Standard General Purpose
**For frequently accessed data**, low latency, and high throughput. Availability of 99.99%

- S3 Intelligent Tier : **For Unknown or changing access**
Works at object level. Automatically moves objects to lower cost tiers if less accessed, with a small monthly object monitoring and automation charge.

```
A new object (Frequent Access Tier) --------> [objects not accessed till 30 days] moved to infrequent access tier, with 40% saving ------> [not accessed till 90 days] moved to archive instant access tier with 68% lower-cost.
```

Still it is immediate retrieval. So, for data that doesn't require immediate retieval, we can set up Intelligent tier to monitor and automatically move objects that aren't accessed for 180 days or more to the deep archive access tier to realize upto 95% in storage cost savings.

*Note: Objects smaller than 128KB can be stored in S3 Intelligent-Tiering but will always be charged at the Frequent Access tier rates, and are not charged the monitoring and automation charge.*

- S3 One Zone Express : **For High Performance**
A single-AZ storage class, for consistent single-digit milisecond of data access, for **most frequently accessed data** and latency sensitive applications. S3 Express One Zone can improve data cess speeds by 10x and reduce request costs by upto 80% compared to S3 Standard. For this, we choose a specific region and its specific AZ, not just a region like other tiers. But with this, data is stored in a directory bucket type and not general purpose bucket type.

- S3 Standard IA : **For Infrequent Access**:
For data that is accessed Less Frequently, but still needs faster access like that of S3 standard with same high throughput, high availability and low latency, but obviously with low costs.

- S3 One Zone IA : **For Infrequent Access**:
Similar to Standard IA, but stores in one AZ, so data maybe lost or unavailable if AZ failure, with same latency, and throughput as S3 standard, but, 20% lower costs than S3 Standard.


Below are for data archiving, with lowest cost archive storage, the most retireval frequency and with the highest performance in the cloud.

- S3 Glacier Instant Retrieval
Lowest cost storage with miliseconds of retrieval. Rarely accessed data. With S3 Glacier Instant Retrieval, you can save up to 68% on storage costs compared to using the S3 Standard-Infrequent Access (S3 Standard-IA) storage class, when your data is accessed once per quarter (once in every 3 months).

- S3 Glacier Flexible Retrieval (Formerly S3 Glacier)
For archive data that does not require immediate access but needs the flexibility to retrieve large sets of data at no cost, such as backup or disaster recovery use cases, choose S3 Glacier Flexible Retrieval (formerly S3 Glacier), with retrieval in minutes or free bulk retrievals in 5—12 hours. Upto 10% lower costs than S3 Glacier Instant Retrieval, but for archived data that is only accessed 1-2 times per year, but asynchronously. Configurable retrieval times, from minutes to hours, with free bulk retirievals.

- S3 Glacier Deep Archive
To save even more on long-lived archive storage such as compliance archives and digital media preservation, choose S3 Glacier Deep Archive, the lowest cost storage in the cloud with data retrieval from 12—48 hours, for data that are accessed once or twice a year.
