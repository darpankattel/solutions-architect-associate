# AWS Simple Storage Service (S3)

AWS S3 is a Storage service, not a database, but block/file storage service, advertised as infinitely scaling. We store files in **buckets** (quite similar to directories), and the files are called **object** instead.

## Usecases
- Static Website
- Data Lake & big data analytics
- Storage, and backup
- Archival
- Media hosting
- Hybrid Cloud storage

## Buckets
Buckets, the *bucket* to store objects, need to have globally unique name, across all regions, and across all accounts. But still, buckets are defined at the region level. We have some strong naming conventions for buckets
- no capitali letters
- 3-63 characters long
- not an ip
- can start with numbers
- must not start with the prefix xn--
- must not end with the suffix -s3alias

## Objects
Objects, or files, have a key, which is the full path to the object, like:
s3://my-bucket/my-file.txt, is the key of the object.

Well, there is no concept of directories in the buckets, but the UI is designed to preview as such for ease.

So, keys are very long, with slashes.

An object can be at max of 5TB in size. But, to upload a file more than 5GB, we should use multi-part upload.

S3 objects have some metadata, like version ID if versioning is enabled.

## Security in S3
### User based
Using **IAM Policies**, we can say which IAM user can access which apis.

### Resource based
- Using **bucket policies**
- **Object ACL**
- **Bucket ACL**


An IAM principal can access an object if:
(User IAM policy allows it) | (resource policy allows) & no explicit deny

Objects are encrypted in S3, in rest and in transit, we will learn about it later.

## Bucket Policies
They are the JSON based policies that have some statements, that provides an **effect** (either allow or deny) for a **principal** of doing an **action** to an **resource**, in some **condition**.

Example:
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowPublicRead", // just the name of a statement, can be anything
            "Effect": "Allow", // Allow | Deny; whether to allow or deny the principal this action on the resource
            "Principal": "*", // the IAM principal can be an IAM User, or roles, etc.. 
            "Action": [ // a action, or *, or list of actions that can be allowed/denied based on effect
                "s3:GetObject", // can get s3 objects within the below listed resource (bucket)
            ],
            "Resource": "*" // expliclitly mention which s3 resource with its ARN or *
        }
    ]
}
```


We can use these above policies to grant public acess to bucket, or force objects to be encrypted at upload, or even grant access to another account.
